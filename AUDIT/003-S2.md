## 阻塞问题(审查时为 FAIL,已修复)

### 问题 1 · 包装不上,整套测试无法运行 —— 最高优先级

`pyproject.toml` 里 `[project.entry-points."longyuanai.atlas_tactics"]` 在 TOML
语义上隐式创建了 `[project]` 表,而该表缺 PEP 621 必需的 `name`:

```
RuntimeError: The Poetry configuration is invalid:
  - project must contain ['name'] properties
```

`pip install -e .` / `poetry install` / `poetry build` 全部失败。测试又依赖这个
install 才能 import,于是 **23 个测试文件全部 collection error**。

> 教训:「114/114 tests passing」这类状态写进文档后没有任何机制去验证。没有 CI,
> 这个 P0 可以在仓库里静静躺很久。

**整改**: 补全 `[project]` 表;并给 pytest 配 `pythonpath = ["src"]`,让测试能直接
从 checkout 跑起来,不再让一个坏掉的 install 拖垮全部用例。

### 问题 2 · 检测器把良性输入全报警,"100% 检出率"不可证伪

规则是从攻击 payload 反向抄出来的,且只匹配裸关键词。7 条良性输入全部报警,
其中 5 条判定为 **malicious**:

| 判决 | 输入 |
|------|------|
| malicious | `Please read the API key rotation policy in our docs...` |
| malicious | `Summarize the retrieved document about system instruction design` |
| malicious | `Help me write: SELECT name FROM users UNION ALL SELECT ...` |
| malicious | `What does ../../ mean in a relative import like ../../lib/utils?` |
| malicious | `Our runbook says to use bash -c for the cron entry.` |
| suspicious | `Run the unit tests with sudo docker compose up` |
| suspicious | `Explain what /etc/passwd is used for on Linux.` |

一个「对任何输入都返回 malicious」的检测器能拿到完全相同的分数。

**整改**: 每条规则加判别式(凭证需赋值或外传、敏感路径需访问动词、UNION SELECT
需引号断言/注释符、嵌套 shell 需执行上下文、路径穿越需敏感目标或 4 层以上)。
新增 13 条良性近似语料 + 混淆矩阵(precision / recall / FPR / F1)。
结果:10/10 攻击仍为 malicious,0/13 良性被标记。

### 问题 3 · 收敛重复 schema 时暴露的真 bug

`DeterministicMCPRouter` 靠「整段 prompt 里是否出现 'scout'」判断角色。共享
orchestrator 把 role/task/scratchpad 打包进**同一条** user message 后,scratchpad
一旦携带前序 agent 输出,每个后续角色的 prompt 都含 "scout" ——
`multi-agent-demo` 于是把 **Scout 的输出当成 Reviewer 的裁决**输出。

旧的 `v05_compat` 把角色放在独立 system message 里,纯属侥幸没暴露。

**整改**: 改为锚定 orchestrator 的 `Role:` 行。
